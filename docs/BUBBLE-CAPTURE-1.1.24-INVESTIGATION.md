## A. Evidence by stage

### OCR and grouping: separate defects

History entry `d0a7bbdd-64da-4fa5-9b49-00a6df18ca49` contains:

- `ELDEST YOUNG MASTER OF THE WOYANG SWORD`, box (277,975)-(574,1104), confidence .67858.
- `HOUSE.`, box (388,1110)-(466,1152), confidence .63477.

The six-pixel gap and horizontally contained final line support the reported split. The name is already `WOYANG` in raw OCR: translation cannot recover `LUOYANG` reliably without independent evidence. Other frames contain `LWOYANG` and `LUOYANWG` before inference.

History entry `d4e79ce5-7de8-4ba1-a34e-f71acae728fd` instead contains one full region: `ELDEST YOUNG MASTER OF THE LUOYANG SWORD HOUSE.`, box (277,844)-(574,1016), confidence .65117. Output is `الأكبر شاب ماجستير في منزل سيف لويانغ.`. Thus grouping sometimes already works, while semantic quality still fails. Joining blocks alone is not a complete semantic fix.

Source inspection: TextRecognitionClient already extracts ML Kit lines, retains block membership during assembly, sorts via DialogueAssembler, and uses same-block OR light/tonal bridge evidence. The cross-block visual probes only accept light backgrounds: TonalCorridor rejects reference channels below150, and LightCorridor requires >=225. The report's surface estimates are black for the problematic text. Dark-background cross-block rejection is a concrete implementation gap, but surface estimates are not the source bitmap: it remains a candidate explanation for this specific frame, not a proven pixel-level cause. The report does not retain original ML Kit block IDs or pairwise merge decisions.

### Translation and names

Whole-region inference already exists in progressiveTranslation/TranslationClient; do not replace it with another engine. Preserve raw OCR separately from normalized translation input. NameShield already masks confirmed glossary names, checks token multiplicity and restores them. It cannot identify a previously unknown name from a corrupted spelling. Case normalization must run behind name shielding and retain mixed-case proper names. No production hardcoding of the example name or full sentence is justified.

### Rendering

Separate successful regions currently receive independent placement. An expanded rectangle may be placed away from its source, so sorting source regions alone cannot guarantee the visible reading order. Full bubble grouping plus source-coverage/placement validation is required. The available report cannot prove actual pixels covered or the reported top/bottom inversion; original screenshots are required for a visual regression fixture. Keeping source on genuine translation failure is intentional and must not be confused with successful full-source masking.

### Punctuation

Stored `.. تحية.` appears in the report. ArabicDisplay already collapses repeated periods to Unicode ellipsis for display and isolates Latin runs. Stored output alone therefore does not establish the rendered bidi order. Add native RTL visual/layout tests, not just string equality, for leading/trailing ellipsis and terminal periods.

## B1. Active + ERROR: demonstrated state-composition defect

At timestamp1795192029988, trace `t-mwp6zf7y-h`, the model installation/inference probe passes. At1795192030986/987, structural validation and block translation fail with `TR-UNTRANSLATED`; the input is `THERE IS NO NEED TO FORCE YOURSELE TO MAKE A SOUND.`. This is an output-validation failure after OCR corruption, not evidence of a MediaProjection or foreground-service failure.

ScreenCaptureService's all-translation-failed branch disables live processing and sets LiveStatus.ERROR while keeping the projection session ACTIVE. BubbleOverlayService.updateControlState concatenates SessionPhase and LiveStatus verbatim (`Capture: ... Active • ERROR`). This directly explains how contradictory visible status can occur. A translation failure must not be relabeled as a revoked projection, and restarting MediaProjection will not fix corrupt OCR/model output.

Needed: one derived, mutually exclusive user-facing status with a typed reason, while retaining separate internal resource/session and work states. Arabic labels must not expose enum names. Clear stale errors at recovery boundaries; test transition sequences, not just individual labels. Retry only recoverable acquisition/execution errors, boundedly. Revoked Android14 projection consent requires fresh user authorization: never replay a consumed token or silently bypass consent.

## B2. Consent launch timeout: evidence does not prove AppOps denial

Distinct raw JSONL entries include four `CAP-CONSENT-BLOCKED` events. In the latest sequence:

- 1795191987669: start requested.
- 1795191992759: consent activity did not enter within5seconds.
- 1795191998108: a new start request.
- 1795191998200: consent activity entered.
- 1795192019596: another consent-entry timeout.
- 1795192024353: later consent activity entered, followed by session activation and acquired frames.

CaptureConsentActivity currently infers a Xiaomi permission block solely from this timeout. It does not query Xiaomi AppOps. The report contains no AppOps value establishing background-popup denial; delayed/blocked activity launch is proven, its vendor-specific cause is not. A later entry under the same trace is not proof that the original generation entered: trace IDs are reused and fresh requests intervene.

Needed: tri-state Xiaomi permission probe (allowed/denied/unknown), with unknown for unsupported/blocked reflection rather than pretending granted. Foreground, Arabic, one-time setup should explain background popups, Autostart, unrestricted battery and recents locking. Vendor permission-editor launch must carry this package, be exception-safe, and fall back to standard app details. Recheck on return; continue the user's pending capture request only when valid. Never promise a background Activity can open while the OS is blocking background launches. Keep a foreground-app recovery path and concise notification/status, not a truncated instruction toast. Android14 service type is already declared; no missing-type exception is demonstrated in this report.
