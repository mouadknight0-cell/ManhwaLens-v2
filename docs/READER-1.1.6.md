# v1.1.6 evidence and implementation

## Evidence
User supplied four Xiaomi Android 14 screenshots of v1.1.4, timings and samples. Visible: translucent overlays bleed original English into Arabic; truncated red error over status bar; browser address translated; Starting/OFF visible without a consent dialog in that still; short `HE...!` untranslated; `NO`/`WAY` remain English amid Arabic. A still cannot establish whether an Activity was blocked or the user dismissed consent.

Records mix versions: many CAP-2014 entries and seven original samples predate 1.1.4. Do not attribute those historical classifications to new code. New 1.1.4 samples explicitly show network-status garbage at y=23/24 and URLs at y=107/112; these incur translation requests and TR-INVALID-OUTPUT. In supplied recent runs, OCR often costs ~383–572ms, versus model readiness ~4–21ms. Run 9 first useful ready is 756.5ms but UI-post is 1950.7ms (1194.2ms gap). Run 12 inference is 1731.9ms. These are different scenes, not a controlled benchmark; no after measurements exist here.

## Root-directed changes
- Floating start previously hid the overlay and waited 250ms BEFORE launching consent. Now the visible overlay remains and the trampoline launches in the tap's main-thread turn. This preserves the visible-overlay background-activity-launch eligibility; Xiaomi may still require its separate background-popup permission. No security bypass or guaranteed OEM success claimed.
- Unique consent generation, activity-entry diagnostic, exception handling and a 5s launch-entry watchdog prevent silently blocked launches leaving STARTING forever. This watchdog does NOT time out a visible consent dialog. Denied/cancelled results still fail and retry; existing sessions reuse projection; consent starts service and Live automatically.
- Reader filter excludes real system-bar/cutout bounds and URL-shaped strings before translation, retaining short dialogue. It is not a general browser-UI classifier; menus can still be translated. No arbitrary fixed top crop.
- Short punctuated OCR lines (`HE...!`, `...A`, `NO!!!`) survive filtering. Adjacent same-height balloons are not merged just because their edges are close. Preserve intentional repeated words/punctuation instead of rewriting emotion. No new multilingual/rotated OCR model.
- Name detection incorrectly treated uppercase `NO WAY` / `HE ...` as names and could persist them. Automatic inference now rejects all-caps candidates and ambiguous English surname homographs. Legacy suspect auto entries remain stored/visible but are not used for shielding; explicit glossary entries remain supported. This trades automatic discovery of uppercase genuine names for fewer false positives. ML Kit remains the translator: no claim of contextual LLM quality, corrected idioms, or cross-panel pronoun understanding.
- Cards are measured at readable font size with padding/line spacing, white opaque rounded background, clamped to absolute system-safe bounds. Long screen-height cards scroll. Android 12+ blocks touch-through opaque untrusted windows, so cards are intentionally touchable: tap to reveal original; swipe in uncovered reader area (or scroll a long card). No invisible touch bypass. Dense-card overlap still needs device evaluation.
- Progressive updates add only new cards rather than removing/re-adding every completed card per block. Bitmap conversion moved off Main onto existing pipeline worker. No unbounded extra OCR passes/concurrency.
- Final rendered partial results can mark T12 without being mislabeled success. Completed processing outcome survives a later scene cancellation; partial counts update as work arrives. UI callbacks verify result ID; T10/T12 remain UI-post proxies, not presentation timestamps.

## Verification and limits
Added JVM regressions for status bars/URLs, short dialogue, adjacent bubbles, uppercase name false positives and preserved repetition. GitHub runs unit tests and builds APK. No attached Android device/emulator: granted/denied/revoked OEM flows, upgrades, gesture handling, large-font/landscape rendering, long-card scrolling, thermal/battery behavior and before/after latency remain unverified. Reproduce supplied panels after upgrade, capture fresh per-version samples, and compare matched stationary scenes before making performance or translation accuracy claims.

Release audit: v1.1.5 was an unsuccessful GitHub build, never signed/published. The additional punctuation-spacing regression fix ships as v1.1.6, leaving the failed tag unchanged.
