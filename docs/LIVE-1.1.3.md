# v1.1.3 live/capture audit and device evidence

## Supplied evidence (v1.1.2, Xiaomi 23106RN0DA, Android 14)
Three distinct failed journeys have CAP-WRONG-SOURCE after successful OCR, with capture session still active. They are not projection initialization failures: frame acquisition and recognition completed. Zero reported regions reflected counts not being updated before the guard, NOT necessarily no OCR text. The guard is heuristic (two app-UI phrases), so the logs alone do not establish whether the actual app was visible, the projection was app-scoped, or the guard matched incorrectly. No screenshot/text is logged to resolve that ambiguity.

Successful journey: OCR 355.275 ms, model readiness 1311.042 ms, translation 926.737 ms, processing 2988.163 ms, first UI marker 4367.286 ms. Reported inferred T12=2988.163 ms preceded T10: this was a real metrics bug. Error log duration_ms values of 129804/187142/191488 ms measured process lifetime, not journey duration. Old 1.1.1 records remain in the report and are not new 1.1.2 measurements.

## Confirmed source problems and changes
- No continuous translation loop existed: Start scheduled one capture. Service now owns one frame-monitor loop and one cancellable pipeline job. MediaProjection frames drive a 32×48 luminance gate; sampling cadence ~70–80 ms; stable gate 180 ms. Meaningful changes cancel obsolete work, clear old overlays and re-arm processing after stability. Unchanged scenes are claimed once. Slow changes accumulate relative to an anchor. These are initial uncalibrated thresholds, not measured device guarantees.
- Frames without a waiter were drained/discarded. A static screen could then time out waiting for a new frame. Retain one newest Image with explicit atomic ownership and close replaced frames. Reader/display teardown releases the retained frame. Frame copy and reader resize are serialized on main; long OCR/translation remain off main.
- Own-window rectangles and system bar bands are excluded from motion samples to reduce feedback from translations and controls. Samples are not persisted. This is visual motion detection, NOT an AccessibilityService scroll event hook.
- MainActivity foreground pauses Live automatically; returning to the reader re-arms the gate. Starting Live while inside ManhwaLens no longer immediately OCRs the home screen. The reported wrong-source error now invalidates projection, sets session=false, closes resources and requires fresh user consent. No token reuse or automatic consent bypass.
- Capture session state is now observable StateFlow; UI observes the service-owned state. Live OFF/WAITING/SCROLLING/PROCESSING/READY/PAUSED_APP/ERROR are published from the same service.
- Cancellable coroutine await did not stop native ML Kit work. OCR now owns a private bitmap until its native Task completes, and a native semaphore prevents overlapping OCR even after cancellation. Translation native tasks are bounded to two until actual completion. Native task execution itself is not forcibly cancellable.
- Translation timeout/error previously returned original text as apparent success and spatial overlay silently omitted it. Failures are now typed per-block, persisted in history and displayed explicitly, excluded from samples and first-useful timing. Invalid/empty non-Arabic output and missing protected names are rejected rather than cached. Cache identity includes original case and current glossary. Name masks now respect word boundaries.
- Unconfirmed T12 is no longer fabricated from T11; legacy inferred values are displayed as unconfirmed. Error logs use request-to-processing duration. Benchmarks include error codes and wrong-source failures record actual OCR region count.

## Quality boundaries
English→Arabic remains the only supported source/target pair. The translator is local ML Kit: there are NO LLM prompts, configurable context windows, token limits or remote response parser to tune. The model receives reconstructed per-region text with protected names; independently merging different speakers to fake context would damage alignment. No claim of fluent contextual Arabic, reliable vertical/stylized-font OCR, or new slang/sarcasm capability is justified without a different evaluated engine. No screen content was uploaded to a new translation provider.

## Tests and release protocol
Pure JVM tests cover stable claim/dedup, sustained/inertia-like motion, slow accumulated motion, repeated swipes/reset, masked overlays, name word boundaries and the observed inferred-T12 contradiction. Existing tests and GitHub APK builds must pass before release. Native model/device behavior is not covered by these tests. Signing remains pinned to the v1.1.1 certificate.

## Remaining device tests / limitations
No physical device or emulator attached. Scroll detection thresholds, actual short swipes/inertia/slow movement, MIUI service restrictions, visual overlay alignment, download failure, battery use and installation/data preservation are UNVERIFIED.
Continuous animation may keep visual detection paused; very small motion confined entirely under excluded rectangles can be missed. Overlay masks and status-bar exclusion need real-device validation. On model or capture errors Live reports ERROR rather than retrying indefinitely; user action may be required. Forced projection revocation always requires new consent. Fully failed translations stop automatic processing. Native tasks may finish after Stop, but cannot publish stale results.
There are no measured v1.1.3 latency/quality improvements. Collect five cold and thirty warm same-page runs, including repeated short/slow/fast swipes, app background/foreground, orientation, permission loss, Stop during model/OCR/translation, and long stable reading. Verify READY returns after each scroll, no old overlays reappear, session status is false after invalidation, and error blocks are visibly marked.
